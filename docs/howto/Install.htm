How to Install Keysharp

Download the package for your operating system from the Keysharp releases page. See Platform Support for desktop-backend and permission requirements.

Prerequisites

Keysharp targets .NET 10. Install the appropriate .NET 10 runtime from the .NET 10 download page if it is not already installed. Building from source requires the .NET 10 SDK.

Windows

Download and run the Windows installer. It can add the install directory to PATH; the entry is removed when Keysharp is uninstalled.

The installer associates .ks source files and .cks compiled scripts with Keysharp. It also adds a right-click Compile action for .ahk and .ks files, which creates a .cks file beside the source script.

Portable use

  1. Download and extract the Windows ZIP package.
  2. Open a terminal in the extracted directory.
  3. Run .\Keysharp.exe yourfilename.ahk.

Building from source

  1. Install Visual Studio 2022 and the .NET 10 SDK.
  2. Open Keysharp.sln and build the solution. Building the installer is not required to run scripts.
  3. Change to bin\Release\net10.0-windows (or the Debug equivalent).
  4. Run .\Keysharp.exe yourtestfile.ahk.

To create the release MSI and portable ZIP, run Keysharp.Install\package-windows.ps1 from PowerShell. Output is written to dist\. The MSI requires the Microsoft Visual Studio Installer Projects extension; the portable ZIP is produced without it.

Linux

Download and extract the Linux installer tarball. Install the Debian package if one is provided, or run:

sudo bash ./install.sh

A system installation:

  • installs runtime dependencies and attempts to install the .NET 10 runtime;
  • associates .ks and .cks files;
  • creates /usr/local/bin/keysharp;
  • installs the root-owned keysharp-inputd daemon for evdev/uinput access, enabling reliable hooks, input synthesis, BlockInput, hotkeys and hotstrings;
  • installs the root-owned setuid keysharp-helper screen-capture trust gate; and
  • installs GNOME and Cinnamon extensions for the invoking desktop user when applicable.

On KWin, keysharp-helper performs ScreenShot2 capture. On GNOME and Cinnamon it is the only caller accepted by the shell extensions. On X11 and other Wayland compositors it records consent before Keysharp performs its own capture; capture cannot be technically enforced there. Without the helper, capture proceeds without this gate where the desktop backend permits it.

The GNOME extension is required for screen capture, mouse-location queries and window automation, and takes effect after logout or reboot. The Cinnamon extension improves window inventory, events, actions and mouse synthesis; the installer asks a running Cinnamon session to load or reload it.

For a user-local installation without privileged helpers, run:

bash ./install.sh

This installs under $HOME/.local. Input hooks/synthesis and Wayland screen capture which depend on the root-installed helpers remain unavailable.

VS Code compatibility shim

For thqby's AutoHotkey v2 Language Support extension, create the executable name it expects:

mkdir -p ~/.local/bin
ln -sf "$(command -v keysharp)" ~/.local/bin/AutoHotkey.exe

Set the extension's interpreter path to /home/YOUR_USERNAME/.local/bin/AutoHotkey.exe. Static language support and running scripts are the most compatible features. Windows-specific debugging, help and compiler integration do not work on Linux.

Building from source

  1. Install the .NET 10 SDK.
  2. Clone the Keysharp branch of Descolada's Eto fork beside the Keysharp repository. For example, from their shared parent directory:
    git clone -b Keysharp https://github.com/Descolada/Eto.git
  3. Run Keysharp.Install/package-linux.sh.

The script writes a portable directory and tarball to dist/keysharp-linux-x64 and dist/keysharp-linux-x64.tar.gz. If dpkg-deb is installed, it also creates a package such as dist/keysharp_<version>_amd64.deb, which can be installed with:

sudo apt install ./dist/keysharp_<version>_amd64.deb

Keysharp is also available as the community-maintained keysharp-git AUR package on Arch-based systems.

macOS

macOS 15 or later is required. Download the osx-arm64 package for Apple silicon or osx-x64 for Intel.

DMG installation

The DMG contains Keysharp.app, Keyview.app, Install.command and Uninstall.command. Double-click Install.command to:

  1. copy Keysharp and Keyview to /Applications;
  2. optionally install the keysharp and keyview terminal commands in /usr/local/bin, which requires an administrator password; and
  3. optionally install the VS Code compatibility shim at ~/.local/bin/AutoHotkey.exe.

Alternatively, drag both applications to the Applications shortcut in the DMG or another directory such as ~/Applications. Keyview locates a sibling Keysharp binary automatically, including when both applications are run from a mounted DMG.

PKG installation

The PKG places both applications in /Applications, then prompts the logged-in user about terminal commands and the VS Code compatibility shim. Double-click the package in Finder, or run:

sudo installer -pkg Keysharp-osx-<architecture>.pkg -target /

First launch and Gatekeeper

Note: Current packages are not notarized. On first launch, Control-click each application, choose Open, then confirm Open in the prompt.

After verifying that the package came from the official release page, quarantine attributes can alternatively be removed in Terminal:

xattr -dr com.apple.quarantine /Applications/Keysharp.app
xattr -dr com.apple.quarantine /Applications/Keyview.app

The terminal commands can be created manually:

sudo ln -sf /Applications/Keysharp.app/Contents/MacOS/Keysharp /usr/local/bin/keysharp
sudo ln -sf /Applications/Keyview.app/Contents/MacOS/Keyview /usr/local/bin/keyview

VS Code compatibility shim

Answer Yes to the compatibility-shim prompt in Install.command, then use /Users/YOUR_USERNAME/.local/bin/AutoHotkey.exe as the interpreter path. Static language support and running scripts are the most compatible features. Windows-specific debugging, help and compiler integration do not work on macOS.

Permissions

Input Monitoring, Accessibility and Screen Recording permissions are requested when needed. See macOS Permissions for the features associated with each permission and how to request them at script startup.

Uninstalling

The bundled uninstaller removes the applications, terminal commands, PKG receipt where applicable, and stored settings/cache data.

  • DMG installation: Open the DMG and double-click Uninstall.command. If the applications were dragged to the Trash manually, eject the DMG and empty the Trash.
  • PKG installation: Run sudo keysharp-uninstall.

macOS Launch Services can continue to open applications from the Trash, so empty it if removed applications remain associated with .ks or .ahk files.

The uninstaller cannot revoke privacy permissions. Remove Keysharp and Keyview in System Settings → Privacy & Security. If permissions become stuck after changing between differently signed builds, reset all TCC entries for both bundle IDs:

tccutil reset All org.keysharp.keysharp
tccutil reset All org.keysharp.keyview

This clears Accessibility, Input Monitoring, Screen Recording and any other recorded permission for all builds sharing those bundle IDs. macOS prompts again when each permission is next required.

Building from source

  1. Install the .NET 10 SDK.
  2. Clone the Keysharp branch of Descolada's Eto fork beside the Keysharp repository:
    git clone -b Keysharp https://github.com/Descolada/Eto.git
  3. Run bash ./Keysharp.Install/package-macos.sh.

The script selects osx-arm64 or osx-x64 from the host. Set RID to cross-publish, for example:

RID=osx-x64 bash ./Keysharp.Install/package-macos.sh

Output in dist/ includes Keysharp-<rid>.dmg and Keysharp-<rid>.pkg. For a quick debug run:

dotnet build Keyview/Keyview.csproj -c Debug
open bin/Debug/net10.0/<rid>/Keyview.app

Signing and notarization are skipped by default. For an ad-hoc signed local build, run:

ADHOC_SIGN=true bash ./Keysharp.Install/package-macos.sh

Verify the Installation

Create hello.ks with this content:

MsgBox "Hello from Keysharp!"

Then run:

Keysharp.exe hello.ks

On systems where the command is installed in lowercase, use:

keysharp hello.ks
