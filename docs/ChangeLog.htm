Recent Changes

This page summarizes the script-visible changes in recent Keysharp releases, so that a script written against an earlier version can be brought up to date. The release page holds the authoritative notes and the downloads for each version.

Note: Keysharp has not reached version 1.0. Behavior can change between releases, including in ways which require edits to existing scripts. Each release below lists its breaking changes first.

0.0.0.17

In development.

Breaking Changes

  • Keysharp-only built-in variables moved into the Ks module, joining those already there, and must be imported to be used: A_AhkBuildVersion, the A_Assembly* family, A_ClipboardTimeout, A_HotIfTimeout, A_InputLevel, A_IsPersistent, A_KeysharpPath, A_LoopKey, A_MaxThreadsBuffer, A_MaxThreadsPerHotkey, A_NewLine, A_PeekFrequency and A_Priority.
  • The assembly-metadata variables are spelled out as A_Assembly* rather than A_Asm* — A_AssemblyTitle, A_AssemblyVersion and the rest — and A_AssemblyName joins them.
  • A_ThreadId was replaced by A_Thread, which is a Thread object rather than a bare number. Its Id property keeps the former layout, so A_Thread.Id reads what A_ThreadId did.
  • The encryption and hashing functions became methods of the Crypt class, so AES, CRC32, MD5, SHA1, SHA256, SHA384, SHA512 and SecureRandom are no longer bare functions. Import the class and call Crypt.SHA256(...).
  • The clipboard functions became members of the Clipboard class. CopyImageToClipboard and IsClipboardEmpty were removed; use Clipboard.Image and Clipboard.IsEmpty. The inherited A_Clipboard, ClipboardAll and OnClipboardChange are unaffected.
  • The monitor helpers became members of the Monitor class. MonitorFromPoint and MonitorGetScale were removed; use Monitor.FromPoint and Monitor.Scale. The inherited MonitorGet family is unaffected. An out-of-range monitor number throws a ValueError rather than silently selecting the primary monitor.
  • Objects handed to a script name their members in spelled-out PascalCase. A size is {Width, Height} and a position {X, Y}, so Image.MeasureText returns {Width, Height}, an Image.Search match is {X, Y} or {X, Y, Color}, and the rectangle WinEvent puts in A_EventInfo is {X, Y, Width, Height}. For the same reason the W and H properties of Monitor, Overlay and Highlight are named Width and Height.
  • Ks.JsonEncode and Ks.JsonDecode became Json.Encode and Json.Decode on the Json class. A JSON null decodes to unset unless the new NullValue option names a stand-in.
  • Assigning unset to a Map element removes it, and reading an element which is not present raises an UnsetItemError.
  • Exit takes only the documented ExitCode; its second parameter, a thread identifier, was removed along with A_ThreadId. To end a thread other than the current one, call Exit on its Thread object.
  • WinEvent's IsPaused property is named Paused.
  • An encoding name which cannot be resolved throws a ValueError rather than being quietly substituted, since the file would otherwise be read or written as the wrong bytes. This applies everywhere an encoding is named, including FileEncoding, FileRead, StrGet and StrPut.
  • Built-in parameter names were corrected to match this documentation, and those which were not valid identifiers were renamed so that named arguments can address them: Part# became PartNumber (StatusBarGetText, StatusBarWait), RootDir\Filename became RootDirFilename (FileSelect), ControlID-or-Pos became ControlOrPos (ControlClick) and YYYYMMDDHH24MISS became Timestamp (FormatTime). Only calls which name a parameter are affected.
  • FuncObj is no longer a name. The function-object class is Func, so MsgBox is Func works and MsgBox is FuncObj does not; the internal name appears only in low-level diagnostics such as stack traces. InputObject likewise became InputHook, and the remaining implementation classes were hidden from global scope.
  • Overlay.Update replaces the overlay's image and geometry in one call. SetImage was removed.
  • Image API changes: DrawText and MeasureText take Gui.SetFont-style Options and FontName arguments in place of one font string, and MeasureText returns an object instead of writing to ByRef variables; Opacity became Alpha; and Search, SearchAll and SearchPixel return a match object and take the region as flat X, Y, W, H parameters.
  • InputHook.OnMouseMove reports movement deltas as (Hook, DX, DY) rather than positions. Per-platform extras, such as the device identifier on Linux, arrive in A_EventInfo.
  • Callbacks are checked when they are registered: one which requires more parameters than the registration site will ever pass — a SetTimer, Hotkey or OnMessage callback — throws there rather than at each invocation. Declaring fewer is allowed, so a hotkey callback may ignore the hotkey name it is handed.
  • Array.IndexOf throws an IndexError for an out of bounds StartIndex (0, or an absolute value exceeding the length), as the sibling FindIndex already did, instead of returning 0. An empty array still returns 0.
  • OwnProps takes no parameters. The undocumented getValues parameter was removed — how many values an iteration yields is decided by the for-loop's variable count — so OwnProps(false) is an error rather than a no-op.
  • OutputDebug takes only the documented Text; its undocumented second parameter was removed. Ks.OutputDebugLine still takes the clear flag.
  • StartsWith and EndsWith take CaseSense, matching InStr, in place of the inverted-sense ignoreCase. Both settings are culture-invariant; only the explicit Locale option consults the current culture.

New

  • Named arguments: an argument can name the parameter it is for (SubStr(s, StartingPos: 2)) instead of relying on its position. A name that matches no parameter is an error, reported before the script runs where it can be (#Warn NamedArg). The name may also be computed with a dereference, as an object-literal key can. NamedArgs is the carrier type, for building or inspecting such a call at run time.
  • Func.Params describes a function's parameters — name, position, whether optional, ByRef or variadic, and any default.
  • The #CSharp directive embeds C# compiled into the script's own assembly, for a hot path a script cannot express efficiently. Each module keeps its own syntax tree and using pool, so aliases do not leak between modules.
  • NuGet packages: the #Package directive resolves one at compile time for Clr and inline C# to use, and Clr.LoadPackage does the same at run time when the dependency is not known ahead of time.
  • The #ConsoleApp directive builds a compiled script as a console application, so a shell waits for it and its standard streams are the terminal's.
  • The #Warning directive reports a message when the script is compiled without failing the build, as the sibling of #Error. It is distinct from #Warn, which configures the runtime's warnings about the script.
  • The Crypt class hashes values and files, encrypts and decrypts with AES, derives keys from a password with PBKDF2, and returns cryptographically secure random values. It gathers the encryption built-ins, which are no longer bare functions.
  • The Clipboard class reads and writes the clipboard as text, images, files, HTML, RTF or a named native format, and can wait for content or watch for changes.
  • The Monitor class describes one display: its geometry, identity and model, scale, brightness and DDC/CI controls, with OnChange for display-configuration changes.
  • The Lock class guards code shared between real threads. It covers the two things LockRun cannot express: acquiring with a timeout, and holding a lock across several statements.
  • Thread is a class as well as a function. An instance describes one script thread — its identity, kind, priority, elapsed time and interruptibility — and can end it. A_Thread is the current one and A_RealThread the real operating-system thread it runs on.
  • The Boolean type names a truth value, so a boolean can be told apart from the Integer 1 or 0 in a type test while reading as 1 or 0 everywhere else. Json.Encode is the visible consequence: a boolean is written as true or false.
  • The Font class carries a font as a value object, with each setting Gui.SetFont takes as a named property, plus the platform's own interface, emoji and monospace families. A Gui and each control expose it as a Font property.
  • ComponentAvailable reports whether the parser or compiler component is installed, compatible and loadable, for a script which must run where the compiler was not deployed.
  • Support for keys which send a combination rather than a single keystroke, such as the Copilot and Office keys. Copilot is a Keysharp alias in static hotkey and remap declarations, which the compiler replaces with the combination <#<+F23 that the key's firmware emits; it is not a runtime key name, so Send, Hotkey and the key-state functions still take the component keys. There is no Office alias.
  • Both terms of a custom combination may carry modifiers (<^a & b::, a & <^b::). Those on the prefix are tested when it goes down and the verdict held until it is released, which is what lets a key whose firmware asserts modifiers and drops them immediately serve as a prefix.
  • Gui.OnMessage and Gui.Control.OnMessage register a callback for a window message ahead of default processing. Window messages are a Win32 concept, so the registration is accepted but never fires on Linux and macOS.
  • SoundPlay and SoundBeep play on Linux and macOS as well as Windows, including the *n standard sounds. macOS plays through afplay; Linux picks the best installed player for the file type, so which formats are available depends on which of them are present.
  • WinEvent.CaretMove fires when the text caret moves, reporting the caret's screen rectangle in A_EventInfo. Move likewise reports the window's new position and size there. Every WinEvent type is delivered on all platforms, subject to each one's event source — see the platform sections on that page.
  • Overlay.OnEvent registers Click, DoubleClick, ContextMenu and MouseMove handlers, receiving coordinates local to the overlay. The overlay must not be click-through to receive them.
  • Gui +DPIResize, with its per-control override, re-lays a window out when it moves to a display with a different DPI. Gui +Round rounds the outer corners of a window which draws its own chrome. The Menu item options Radio, Right, RTL, Break and BarBreak are supported, with per-platform limits noted on that page.
  • Json.Encode takes an Indent option to pretty-print, and Json.Decode a CaseSense option setting the key comparison of every decoded Map.
  • DirCopy extracts .zip, .tar, .tar.gz and .tgz archives, and decompresses a plain .gz to a file. Keysharp extracts them itself, so the supported formats do not vary by operating system.
  • Array.Remove returns whether it removed anything, and Contains, IndexOf and Remove search for an element which has no value when Value is omitted.
  • File.Read takes an optional character count; omitting it reads the rest of the stream.
  • FileEncoding and everywhere else an encoding is named accept any encoding .NET recognizes, such as windows-1252, alongside the names AutoHotkey accepts.
  • #Import accepts a relative path, binding the leaf name, and a module whose function or class shares its name exports that as the default. A backslash is accepted as a path separator on every platform in #Include, #Import and #CSharp paths.
  • Clr accepts a script Integer where a .NET enum is expected, including a combination of flags which has no declared name.
  • A_ProcessArch and A_OSArch report the CPU architecture of the process and of the operating system. Interop code should branch on A_ProcessArch rather than A_PtrSize, which cannot tell X64 and ARM64 apart.
  • The compatibility target moved to AutoHotkey v2.1-alpha.30, bringing typed parameter and return signatures for CallbackCreate, ObjSetBase, and the numeric type classes and further struct members.
  • Ks.FileCreateTemp creates an empty temporary file and returns its full path.

Platform

  • Windows: ARM64 builds, and a WiX-based installer in place of the Visual Studio Installer project. InputBox was reimplemented on the native dialog.
  • Linux: mouse input on wlroots-based compositors (Sway, Hyprland, Wayfire, labwc) through zwlr_virtual_pointer_v1, falling back to uinput when compositor injection fails. A script's own Wayland windows are placed, claimed and reported under the handle the script holds, so window and control geometry resolve against the compositor's surface origin. Overlays on KWin and wlroots receive mouse input through their layer-shell surfaces; compositor-drawn overlays on GNOME and Cinnamon cannot yet.
  • macOS: osx-x64 builds for Intel Macs are published alongside osx-arm64. macOS 15 or later is required.
  • Linux and macOS: the main window's About dialog, and the status bar reporting which part was clicked.

Fixes and Performance

Send restoring modifiers from a stale snapshot in SendEvent mode, #Warn reporting the wrong line inside an included file, #Import creating a setter for a read-only property, overriding a built-in class's __Enum, continuation sections, switch and Loop Files condition parsing, and a leading comma in a function call statement. A_MyDocuments, A_Desktop and the four A_*Common folders resolve correctly. GUI fixes cover control addressing by ClassNN, xs/ys anchoring in Tab3 pages, measuring a control created hidden, a checkbox reporting its own state, and rejecting a control callback which does not resolve. #HotIf criteria are evaluated through a cheaper executor, and script processing is split into optional components so a deployment can omit the compiler.

0.0.0.16

Released 19 July 2026.

Breaking Changes

  • ImageCapture() was removed. Use the Image class instead.
  • Linux input requires the keysharp-inputd daemon; the SharpHook and X11 fallbacks were removed. See Platform Support.
  • A_ScaledScreenDPI was renamed to A_ScreenScale.
  • A_OSType now returns WINDOWS, OSX or LINUX.
  • A_LineFile in the main file resolves to the main script's full path, as A_ScriptFullPath does.
  • #Import inside a function or class body binds to that scope, and an unknown import throws.
  • Reserved words can no longer be used as variable names.
  • Invalid Gui options now throw instead of being ignored.

New

  • Image captures, loads, creates, draws, transforms, searches and manipulates pixels before saving. It replaces ImageCapture().
  • Overlay is an always-on-top, click-through canvas using the same drawing primitives as Image. It now backs Highlight and ToolTip on Linux and macOS.
  • WinEvent subscribes to window events across platforms: Active, Exist, NotExist, Move, Minimize, Restore and TitleChange.
  • Thread identity, and Exit targeting a thread other than the current one.
  • OnMouseDown, OnMouseUp and OnMouseMove on InputHook.
  • Fully cross-platform monitor functions, plus MonitorGetScale and MonitorFromPoint in the KS module.
  • Gui +ClickThrough and +AutoScroll options.
  • An *Dir scan-direction option for ImageSearch.
  • An OCR library (OCR.ks) with a pluggable engine, and demo scripts including ClipboardHistory, InputHUD, OCRSnip, Shell, WindowGrab and WindowTiler.

Platform

  • Linux: all input channels now go through keysharp-inputd (evdev and uinput), reworked for multi-user handling, per-script permissions, Unicode sending and mouse buttons.
  • Wayland: overlays, clipboard and window manipulation through KWin scripting and Keysharp shell extensions for GNOME (including v48 and later) and Cinnamon.
  • macOS: the hook and sender were revamped on CGEventTap and the key sender is now functional. Binaries are signed, and releases include DMG and PKG packages with SHA256 checksums.

Fixes and Performance

Release-mode stack traces for C# exceptions, OnExit teardown, script exit when the last window closes, thread priority handling and DLL path normalization. Parser fixes for #Include, static variables, dereferences and remap syntax. Regular-expression pattern caching, font caching, cheaper per-call thread setup and faster keyboard-layout queries.

0.0.0.15

Released 22 June 2026. This release made Keysharp cross-platform across Windows, Linux and macOS.

  • macOS support: window management, the keyboard and mouse hook and sender, sound and drive functions, App Switcher integration and native Command-key handling, plus AxSpy, an accessibility inspector.
  • Linux: the inputd input daemon, .deb packaging with automatic .NET 10 installation, Unicode character sending and Keyview syntax highlighting.
  • New parser: a hand-written parser replaced ANTLR4, which is faster and less ambiguous.
  • AutoHotkey v2.1 features: the v2.0 and v2.1 compatibility modes, structs with #StructPack, the #Import directive, PropRef, the !~= operator and ahk_opt.
  • Scheduler: the timer and event scheduler was reworked, fixing timer livelock and timers not firing inside hotkey callbacks.
  • Cross-platform GUI on Eto: DPI scaling, dialog theming, hyperlink labels and A_GuiTheme.
  • The hook and sender were brought current with AutoHotkey 2.0.26.
