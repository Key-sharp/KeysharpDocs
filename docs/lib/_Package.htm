#Package [Keysharp]

Makes a package's assemblies available to the Clr object and inline C#. The script does not start if a required package cannot be made available.

#Package *i Provider:PackageId Version

Requirements: Keysharp's bundled NuGet provider runs the official NuGet restore engine inside the Keysharp process. It requires only the .NET runtime already needed by Keysharp — not the .NET SDK, MSBuild, dotnet, nuget.exe or another NuGet executable. A cold package set can still require network access to a configured feed. See Resolution and caching.

Parameters

Provider

Type: String

The local package-system provider. If omitted, this is nuget, so #Package Newtonsoft.Json and #Package nuget:Newtonsoft.Json are equivalent. A provider name begins with a letter and contains only letters, digits, - or _.

Providers are installed as loose payloads under Keysharp's components/packages/<name> directory and are loaded only when used. An installation can therefore add another package system without changing this directive; for example, #Package aris:dev/name would pass dev/name to an installed aris provider. Keysharp does not download missing providers.

PackageId

Type: String

The identifier understood by the selected provider. For NuGet this is the package identifier as it appears on the feed, such as Newtonsoft.Json, and may contain letters, digits, ., _ and -. Other providers validate their own identifier forms.

Version

Type: String

The selected provider validates and interprets this text. The bundled NuGet provider accepts the same AHK-style shapes #Requires accepts. An optional letter "v" may precede a version number.

WrittenMeaning
omittedThe newest stable release.
v13 or 13The newest 13.x release.
v13.0 or 13.0The newest 13.0.x release.
13.0.3Exactly that version.
>=13.0, <14, >=13.0 <14A bounded range. <, <=, >, >= and = are accepted.
13.*A floating version.
[13.0,14.0)A NuGet interval.

Whatever is written, the version actually chosen is pinned: it is recorded in the resolved package set and, for a compiled script, in the script assembly itself. A later run therefore does not silently change dependencies.

Prerelease versions are not selected unless the version says so explicitly (for example 1.0.0-beta.1).

Note: This parameter is not an expression. Neither parameter accepts variable references.

*i

If present, the package is optional: if it or its separately installed provider cannot be made available, the script continues without it instead of stopping. The reason is reported through OutputDebug. If the provider is installed, malformed provider-specific package or version syntax is still an error.

Use this only when the script can actually run without the package, such as a feature that degrades gracefully. Note that the eventual failure is less informative — instead of a resolution error naming the package, the script fails later at the point a type from it is used.

Resolution and caching

Each package system is implemented by a local provider. The bundled NuGet provider uses the official NuGet client libraries in-process to choose the right build for the current framework, resolve dependencies, reconcile versions, select platform-specific native files, access feeds and maintain the global package folder. No SDK, MSBuild or external executable is invoked.

Resolution happens when the script is compiled, not when it runs. The exact version each request resolved to is recorded inside the built script, and that is what loads on every later run — so a floating version such as #Package Newtonsoft.Json is decided once, by the build, rather than being decided again by each machine that runs it. This is the arrangement a .NET project uses, and it is what lets inline C# using a type from a package the script declares: the compiler knows those assemblies because it resolved them itself.

Resolution happens in this order:

  1. If the requested set, provider version and relevant configuration match a successful cached graph whose assets still exist, that graph is used without network access.
  2. Otherwise the selected provider resolves the set. The NuGet provider can use the global package folder and any enabled feeds, so a cold set might require network access.
  3. The compiler records the exact resolved graph and assets in the script manifest. Runtime startup reads that manifest and never calls a provider or restores the declarative set.

Note: --validate and Ks.ParseScript never restore. They are checks rather than builds, so a package set that has not been restored on this machine yet is reported as exactly that instead of triggering a download — which matters most in an editor, where a check may run every time you stop typing. Running or compiling the script restores it.

The NuGet provider discovers NuGet.Config beginning at the script directory. Its enabled package sources, credentials, package-source mapping, trusted-signer policy, global-packages folder, fallback folders and ordinary NuGet feed/network behavior apply. Feed URLs, proxies, mirrors and source policy therefore belong in NuGet configuration rather than in this directive. Changing a discovered config file or enabled source invalidates the cached graph.

Keysharp's cache stores per-set resolution metadata. Package contents live in the global packages folder selected by NuGet configuration (%NUGET_PACKAGES% when set, otherwise the NuGet default), shared with other .NET tooling.

Package compatibility: Keysharp consumes managed compile/runtime assemblies, resource assemblies and native libraries selected for the current runtime. It does not execute package MSBuild props or targets, custom tasks, analyzers, source generators or contentFiles. A package which requires one of those build-time hooks is not suitable for this directive even if its dependency graph restores successfully.

Remarks

Every #Package directive in a script is resolved together, grouped by provider, and each must appear at the top level of a script or module. Resolving them separately could settle on two different versions of a shared dependency and load both, so requesting the same provider/package identity twice with different versions is a load-time error. Requesting it twice with the same version is accepted and has no additional effect.

Types from a package's own dependencies are reachable too, even though the script never names those packages. A dependency is not loaded until something is actually used from it.

No further syntax is needed to use what was made available: types are reached through Clr by namespace, in the ordinary way.

Like other directives, #Package cannot be executed conditionally.

If the NuGet provider reports a known security advisory for a resolved package, the advisory is passed through to OutputDebug and the script continues.

This is not #DllLoad. That directive loads a native module so DllCall can reach it, and has no effect on what Clr can see — pointing it at a .NET assembly does not make that assembly's types available. Use #Package for packages, or Clr.Load for a .NET assembly already on disk.

Security: A package is third-party code, and it runs inside the script's process with the script's full privileges. Packages are not reviewed, vetted, or endorsed by this project; the trust decision is the same one a .NET project makes, and it is the script author's. Treat an unfamiliar package name with the same caution as an unfamiliar DLL.

Compiled scripts: A compiled script carries the exact declarative package assets it was built against, so the target machine needs neither a provider, network access nor a populated package cache for #Package. A normal executable or raw .cks stores them in a private package/version-scoped .keysharp/packages hierarchy beside the output; distribute that directory with the artifact. An exe-min embeds the assets in the generated script assembly instead. Same-named files from different packages cannot overwrite one another. If an asset is missing at startup, the script stops with an error naming the package and version rather than failing later when a type is used.

For the cases a directive cannot express — a package chosen by a computed name, or one needed only on some code paths — see Clr.LoadPackage. Prefer this directive where it fits: it resolves every package in one step, pins the result, and needs no provider at runtime.

Examples

Requires a specific version of a package, then parses JSON with it.

#Package Newtonsoft.Json 13.0.3
#Import "Ks" { Clr }

Obj := Clr.Newtonsoft.Json.Linq.JObject.Parse('{"name":"Keysharp","version":2}')
MsgBox Obj["name"].ToString()

Takes the newest 13.x release, and marks a second package optional so the script still runs without it.

#Package Newtonsoft.Json 13
#Package *i Serilog >=4.0 <5
#Import "Ks" { Clr }

MsgBox Clr.Newtonsoft.Json.JsonConvert.SerializeObject([1, 2, 3])

Uses a type from a dependency the script never names. SQLitePCL.raw comes from SQLitePCLRaw.core, pulled in as a dependency, and the database engine itself is a native file the package supplies for this platform.

#Package SQLitePCLRaw.bundle_e_sqlite3 2.1.10
#Import "Ks" { Clr }

Clr.SQLitePCL.Batteries_V2.Init()
MsgBox Clr.SQLitePCL.raw.sqlite3_libversion_number()
