Taskbar

class Taskbar extends Object

The badge and progress bar a desktop shell draws on a taskbar button.

Called on the class, it decorates the application's own button. That is what Linux and macOS do in any case, so it is the form which means the same thing on every platform:

Taskbar.SetProgress(40)

It behaves as one application-wide setting: every call replaces the last, on the windows already open as well as on those opened afterwards, so no window is left showing an earlier badge. It can therefore be set before any window exists. On Windows, where the shell decorates a button rather than an application, that is done by giving each button the same decoration — when it is set, and again as each new window is shown. A per-window call overrides it for that window until the next application-wide one.

Constructed with a window handle, it decorates that one window's button — a distinction only Windows makes, see IsPerWindow:

Taskbar(MyGui.Hwnd).SetProgress(40)

This is not the taskbar button's own icon, which is the window's icon: set that with Gui.SetIcon or TraySetIcon. This is the small badge drawn over it, and the progress bar drawn inside it.

The class is exported by the KS module:

#Import "Ks" { Taskbar }

Taskbar()

Constructs a Taskbar for the window with the given handle, this script's own or any other's. Omit the constructor entirely — Taskbar.SetProgress(40) — to decorate the application's own button instead.

TaskbarObj := Taskbar(Hwnd)
Hwnd

Type: Integer

The window handle whose taskbar button is decorated. A handle of 0 raises a ValueError.

The shell takes its own copy of whatever it is given, so a Taskbar object holds no resources and what it draws outlives it. It is equally correct to keep one for the life of a window or to build one for a single call. The decoration belongs to the window, not to this object, and goes when the window does.

Note: Off Windows the handle is ignored, because the shell decorates the application rather than one of its windows. A script which wants that behaviour everywhere should call the class form.

SetBadge

Draws a badge over the window's taskbar button.

TaskbarObj.SetBadge(Source, IconNumber, Text)
Taskbar.SetBadge(Source, IconNumber, Text)

The first form badges TaskbarObj's window; the second badges the application's own button.

Parameters

Source

Type: String

If omitted or blank, the badge is removed. Otherwise the path to an icon or image file, a module holding icon resources such as "shell32.dll", or a handle such as "HICON:" handle. Platforms which cannot draw an icon badge ignore this and show Text instead; see HasBadgeIcon.

IconNumber

Type: Integer

If omitted, it defaults to 1 (the first icon group in the file). If negative, the absolute value is assumed to be the resource ID of an icon within an executable file, as in Gui.SetIcon.

Text

Type: String

What the badge means, which Windows exposes to a screen reader. On Linux and macOS this is what the badge shows: a number on Linux (text which is not a number shows as 1), a short string on macOS.

SetProgress

Fills the window's taskbar button with a progress bar.

TaskbarObj.SetProgress(Value, Maximum)
Taskbar.SetProgress(Value, Maximum)

The first form fills TaskbarObj's window's button; the second fills the application's own.

Parameters

Value

Type: Integer

If omitted or blank, the bar is removed. Otherwise how far along the work is, out of Maximum.

Maximum

Type: Integer

If omitted, it defaults to 100, so Value reads as a percentage. Zero or less removes the bar, as a blank Value does.

SetProgressState

Sets the kind of progress the bar shows, which is what makes it amber, red or a marquee.

TaskbarObj.SetProgressState(State)
Taskbar.SetProgressState(State)

The first form applies to TaskbarObj's window; the second to the application's own button.

Parameters

State

Type: String

One of the following, matched without regard to case. Anything else raises a ValueError.

StateMeaning
NoneRemoves the bar.
NormalAn ordinary bar, green on Windows.
IndeterminateA marquee; the value is ignored.
PausedAmber on Windows.
ErrorRed on Windows.

HasBadgeIcon

Whether this platform can draw an icon as the badge.

Boolean := Taskbar.HasBadgeIcon

False on Linux and macOS, which have only a number or a short string, so a badge set there shows its Text instead.

IsPerWindow

Whether the badge and progress belong to one window.

Boolean := Taskbar.IsPerWindow

False on Linux and macOS, where they decorate the whole application, so two windows setting them there overwrite one another.

Platform Differences

Only Windows has all of this. Nothing here reports whether the shell drew anything, because two of the three platforms cannot say; ask HasBadgeIcon and IsPerWindow once instead of checking a result on every call.

PlatformBadgeProgressScope
WindowsThe icon, drawn over the buttonA bar inside the button, in the colour the state namesOne window
LinuxText read as a numberA fraction on the launcher icon; Error also raises the urgent hintThe whole application
macOSText as dock tile badge textA bar drawn on the dock tileThe whole application

Note: On macOS the underlying toolkit also asks for the user's attention when progress completes or fails, which bounces the dock icon until the application is activated. That is a side effect of how the dock tile is driven, not something this class requests.

Linux uses the Unity LauncherEntry protocol, which carries a number and a progress fraction rather than an icon, and which reaches only docks that implement it — Ubuntu's, Dash to Dock, Plank and Latte among them. A dock which does not implement it ignores the request silently.

The launcher icon a Linux dock decorates is the one named by the DESKTOP_ENTRY environment variable, the same variable libunity consumers use, defaulting to Keysharp's own entry. An application which installs its own .desktop file should set it in its launcher, or from the script before its first call:

EnvSet("DESKTOP_ENTRY", "myapp.desktop")

Examples

Reports the progress of a long job on the taskbar, and badges the button while the work runs.

#Import "Ks" { Taskbar }

MyGui := Gui(, "Downloading")
MyGui.Show("w300 h100")

Taskbar.SetBadge("shell32.dll", 46, "Downloading")

Loop 100
{
    Taskbar.SetProgress(A_Index)
    Sleep 30
}

Taskbar.SetProgress("")     ; Remove the bar.
Taskbar.SetBadge("")        ; Remove the badge.

Turns the bar red when the work fails.

#Import "Ks" { Taskbar }

MyGui := Gui()
MyGui.Show()

try
    Download("https://example.com/missing.zip", A_Temp "\missing.zip")
catch
{
    Taskbar.SetProgress(100)
    Taskbar.SetProgressState("Error")
}

Badges a window belonging to another process. The badge stays until it is cleared or the window closes, whether or not the object is kept.

#Import "Ks" { Taskbar }

Taskbar(WinExist("ahk_exe notepad.exe")).SetBadge("shell32.dll", 174, "Watched")
