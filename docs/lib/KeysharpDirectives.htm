Keysharp Build Directives

Conditional Compilation

#If Expression
#ElIf Expression
#Else
#EndIf
#Define Name
#Undef Name

Selects which source is compiled. Only the active branch reaches the compiler; excluded code is removed before parsing, so it need not be valid beyond its conditional structure. These follow the C# preprocessor rather than the AutoHotkey v1 #If directive, which set hotkey context and has no equivalent here — use #HotIf for that.

Directives are resolved per physical line, so a block may split a single statement:

x := (
#If WINDOWS
    1
#Else
    2
#EndIf
)

Each directive owns its own line: the condition runs to the end of the line, so the whole block cannot be written on one line.

Predefined symbols

Symbol names are case-insensitive and carry no value; a symbol is either defined or it is not. The following are predefined:

SymbolDefined when
KEYSHARPAlways.
WINDOWS, LINUX, OSXExactly one, matching the platform the running Keysharp build targets.
DEBUGOnly in a debug build of Keysharp itself.

#Define adds a symbol from that point in the file onward and #Undef removes one. --define:NAME predefines symbols for a whole compilation, including any module it imports.

Conditions

A condition may combine defined symbols, true and false, integers (zero is false, in any spelling), !/not, &&/and, ||/or, and parentheses. An undefined symbol is false. A name which is both defined and spelled true or false is treated as the symbol.

There is no defined() operator and no comparison operator; a condition is a symbol test, not an expression. Anything outside this grammar is a compile-time error rather than a silently false condition, so #If defined(WINDOWS) and #If WINDOWS == 1 are both rejected. Conditions are checked even in branches which are excluded, so a malformed one is reported on every platform.

#Else and #EndIf take no condition. Unbalanced, duplicated, or misplaced directives — a missing #EndIf, a second #Else, an #ElIf after #Else, or any of these without an open #If — are compile-time errors.

A #Define made in an #Included file is visible to the rest of the including file, because an include is spliced into the same compilation. An #Imported module is compiled separately and once, shared by every importer, so it does not see the importing script's symbols; use --define to configure one.

#Error and #Warning

#Error Message
#Warning Message

Emits Message when the script is compiled, reported against the directive's own line. #Error fails the compilation; #Warning does not, and is written to standard error while the script still runs. Both are commonly paired with conditional compilation:

#If !WINDOWS
#Warning This script has only been tested on Windows.
#EndIf

The message is free-form text taken verbatim to the end of the line, so quotes, commas, apostrophes and braces in it are literal. Both directives are permitted wherever a directive is, including inside a function, class, or block, and neither is reported when it lies in a branch which conditional compilation excluded.

#Warning is distinct from #Warn, which configures the runtime's own warnings about the script; its Off, StdOut and MsgBox modes do not apply here. A #Warning is a message to whoever builds the script, so it is not carried into a compiled executable and does not reappear when that executable runs.

#ConsoleApp

#ConsoleApp

Builds a compiled executable as a console application, so a shell waits for it to finish and its standard input and output are the terminal's. This is the equivalent of AutoHotkey's Ahk2Exe ConsoleApp directive.

A graphical application remains the default, so a script started by double-clicking never flashes a console window.

The directive is ignored when the script is interpreted or compiled to a .cks file, since neither writes an executable.

Note: On Windows this is recorded in the executable's PE subsystem, which is fixed before the process starts, so it cannot be changed while the script runs. On Linux and macOS executables have no subsystem and a shell always waits, so the directive is accepted and has no effect.

#HookMutexName

#HookMutexName Name

Changes the name of mutex objects used to detect keyboard and mouse hooks in other scripts. The default is Keysharp.

Assembly Metadata

#AssemblyTitle Value
#AssemblyDescription Value
#AssemblyConfiguration Value
#AssemblyCompany Value
#AssemblyProduct Value
#AssemblyCopyright Value
#AssemblyTrademark Value
#AssemblyVersion Value
#AssemblyName Value

Sets the corresponding .NET assembly attribute on compiled output. #AssemblyVersion sets both the assembly and file version.

#AssemblyName is the exception: .NET has no AssemblyNameAttribute, so rather than emitting an attribute it sets the compiled assembly's identity — what Assembly.GetName().Name reports. It overrides the name otherwise taken from the script's file name. Each of these is readable at run time through the matching A_Assembly* variable.
