Clr Object

Provides experimental access to .NET assemblies through ordinary script property, method, call and index syntax.

This class is exported by the KS module.

Experimental: Basic values and function objects are marshalled, but complex .NET types might not convert correctly.

Load

Root := Clr.Load(AssemblyOrPath)

Loads a DLL/executable path or assembly name and returns a ManagedAssembly or ManagedNamespace wrapper. This is a local operation: it never retrieves anything. To use a library from a package feed, see #Package.

LoadPackage

Package := Clr.LoadPackage(Provider:Name , Version, Optional)

Makes a package's assemblies available at run time, and returns a ManagedAssembly over that package's own assemblies. Its types are then reachable both from the return value and through Clr by namespace. The default provider is nuget; a prefix such as aris:dev/name selects another locally installed provider and passes the remainder of the name to it.

Version takes the same forms as the #Package directive: omitted for the newest stable release, or partial, exact or bounded. If Optional is true, a package or separately installed provider that cannot be made available returns an empty string instead of raising an error. Malformed package or version syntax remains an error when the provider is installed.

Prefer #Package where it fits. Package resolution considers all requested packages together, and resolving in one step is what stops two packages settling on different versions of a shared dependency. This function accumulates — each call re-resolves everything requested so far, including packages named by the directive — but assemblies already loaded by an earlier call cannot be unloaded, so a genuine version conflict is reported rather than repaired. Use this function for what a directive cannot express: a package chosen by a computed name, or one needed only on some code paths.

Compiled scripts: This function needs its selected provider at run time. A normal compiled executable carries a statically visible provider under components/packages/<name>; exe-min embeds the provider payload, verifies it and extracts it under the current user's local application-data directory when first used. A raw .cks is run by Keysharp and uses the provider shipped with that launcher, so it does not copy the provider beside every assembly. A non-default provider hidden entirely inside a computed name must be installed beside the target artifact because the compiler cannot infer it.

Namespaces, Types and Instances

  • Access a ManagedNamespace property to retrieve a child namespace or ManagedType.
  • Access static methods and properties through a ManagedType, or call it to construct a ManagedInstance.
  • Use ordinary property, method and index syntax with a ManagedInstance.

Enum Values

A script has no enum type, so a member of a .NET enum is named by its Integer:

#Import "Ks" { Clr }
System := Clr.Load("System")
System.IO.File.SetUnixFileMode(Path, 0o600)

The value does not have to be a declared member, so a flag combination can be built in script with |. The member itself works equally well when read through a ManagedType, as in System.StringComparison.OrdinalIgnoreCase.

An enum returned from .NET arrives as a wrapper rather than as an Integer, because a script has nothing to widen it to; use ToString for the member name. A value with no numeric reading raises a TypeError, as it does for any other whole-number parameter.

Name Helpers

Name := Clr.GetNamespaceName(ManagedNamespace)
Name := Clr.GetTypeName(ManagedType)

Returns the underlying full namespace or type name.

ToClr on built-in objects

Built-in objects which stand in front of a CLR object expose it with a uniform ToClr() method, returning it as an ordinary Clr object with the member-access semantics described above: Task (the underlying CLR task, so a worker's body is reached as worker.Task.ToClr()), Gui, Gui.Control and Menu (the backing toolkit object, whose concrete type is platform-dependent and unspecified), and Image (the live underlying bitmap, with pending drawing applied first).

Map and Array are themselves CLR objects — a Map is a CLR IDictionary<object, object> and an Array an IList, so a CLR API declaring one accepts them directly — and their ToClr() exposes their full CLR surface late-bound.

Changes made through the wrapper bypass the owning class's own state and event wiring.

#Import "Ks" { RealThread, Await }
worker := RealThread(() => 42)
Await(worker.Task)
MsgBox worker.Task.ToClr().IsCompleted

Inline C# (#CSharp) holding a ManagedInstance reads the raw wrapped object from its Native property. Script member access on a wrapper always dispatches to the wrapped object, so Native is unreachable from script.

Examples

#Import "Ks" { Clr }
System := Clr.Load("System")
Linq := System.Linq.Enumerable
Odds := Linq.Where([1, 2, 3, 4], n => Mod(n, 2))
