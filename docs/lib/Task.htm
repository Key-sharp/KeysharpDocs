Task Object

class Task extends Object

Work that finishes later.

This class is exported by the KS module.

Every CLR call which returns a .NET Task hands one of these back, as does an async Task<T> member in a #CSharp block, so both surfaces describe work in flight the same way.

Await is how a script waits for one and reads its value.

Call

TaskObj := Task(ClrTask)

Wraps a CLR Task or ValueTask reached some other way. A task returned from a CLR call is wrapped already and needs no conversion.

Result

Value := TaskObj.Result

The value this task produced, or an empty string while it is still running, if it failed, or if it produced none.

Note: This is a snapshot and never waits, exactly as RealThread.Result does not. It is not the .NET Task.Result, which blocks. Await and Wait are the waiting forms.

Status

State := TaskObj.Status

"Running" until the work finishes, then "Done", "Error" or "Canceled".

Error

Err := TaskObj.Error

The failure as a catchable Error object once the task has failed, otherwise an empty string. Reading it counts as observing the failure, so it is not also reported as an uncaught error.

Clr

ClrTask := TaskObj.Clr

The underlying CLR task as an ordinary Clr object, so members this class does not mirror — IsCompleted, Exception, ContinueWith — stay reachable. Note that Clr.Result is the .NET one, which blocks the whole thread; Result and Await exist so you do not have to.

Warning: Waiting through this surface — Clr.Result, Clr.Wait(), Clr.GetAwaiter().GetResult() — blocks the thread without checking messages. Work which still has to run on that same thread then never gets the chance, so such a wait can last forever. Await and Wait pump while they wait and do not have this problem; if you take the raw surface, keeping the thread pumping is up to you.

Wait

Finished := TaskObj.Wait(Timeout)

Waits for the task, returning 1 (true) if it finished or 0 (false) if Timeout elapsed first. Timeout is in milliseconds; omit it to wait indefinitely.

Like Await, this pumps while it waits, so timers, hotkeys and the GUI stay responsive. Unlike Await it does not throw on failure — read Status and Error afterwards.

Then

NextTask := TaskObj.Then(Callback)

Runs Callback once this task finishes, without blocking. Returns a new Task which finishes when the callback has run, so calls chain.

MyCallback(TaskObj)

Callback receives the Task as its only parameter and reads Result, Status and Error from it. It may declare no parameter at all if it does not want the task.

The callback runs on the script thread which owns the task, in its own script thread, so A_* variables, Critical and GUI access all behave normally.

The returned Task carries the callback's own outcome — its return value, or its failure — so Await on a chain reports what went wrong instead of resolving to nothing. Then does not flatten: a callback which returns a Task yields a Task whose Result is that inner task.

WhenAll / WhenAny

TaskObj := Task.WhenAll(Tasks*)
TaskObj := Task.WhenAny(Tasks*)

WhenAll finishes when every one of Tasks has finished, and its Result is an Array of their results in the order given. If any of them fails, so does it.

WhenAny finishes as soon as the first of Tasks finishes, and its Result is that one's. The others keep running; nothing here cancels them.

Both accept a RealThread as well as a Task. A RealThread reports a failing body on its own thread, so it contributes its Result — empty on failure — rather than a failure; RealThread.Main and adopted threads have no body to wait for and raise a TargetError.

Source

SourceObj := Task.Source()

Creates a task the script settles itself, returning a TaskSource object with three members:

SourceObj.Task                     ; the Task to hand to Await, Then, WhenAll or WhenAny
Settled := SourceObj.Resolve(Value)   ; finish it successfully
Settled := SourceObj.Reject(Reason)   ; finish it as failed

This is how a callback-shaped source of events — a hotkey, a GUI control, a device notification — takes part in WhenAny or is handed to Await. Without it a script could only ever consume tasks the CLR produced, never make one.

Reason may be an Error object, which is what Await rethrows and Error hands back, or a string describing one.

Settling is one-shot and idempotent: the first Resolve or Reject decides the outcome and returns 1 (true), and every later call returns 0 (false) without raising. That is what makes it safe to use from several handlers racing each other, which is the point.

Remarks

Exactly one Task object exists per underlying piece of work, so identity comparison answers whether two references describe the same work.

There is deliberately no Cancel: .NET cannot cancel a task it did not create. Cancellation is a token passed into the call which produced the task, which a script can do through Clr:

cts := Clr.System.Threading.CancellationTokenSource()
t := api.FooAsync(url, cts.Token)
cts.Cancel()

Status then reports "Canceled".

There is likewise no Delay, Completed or Run. Clr.System.Threading.Tasks.Task.Delay(ms) and .FromResult(value) both come back as Tasks through the ordinary boundary — Delay in particular is what WhenAny races against for a timeout — and RealThread runs script code on another thread, which a thread-pool task cannot do because a script function belongs on a thread owning a script-thread stack.

A failure nobody ever looks at is reported as an ordinary script error when the task is collected. That is the same moment .NET reports an unobserved failure, which matters: a task you are about to Await is never reported out from under you.

Examples

Waiting for an asynchronous .NET call without freezing the script.

#Import "Ks" { Task, Clr, Await }

http := Clr.System.Net.Http.HttpClient()
body := Await(http.GetStringAsync("https://example.com"))
MsgBox StrLen(body) " characters"

Running two pieces of work at once, then joining them.

#Import "Ks" { Task, Clr, Await }

http := Clr.System.Net.Http.HttpClient()
a := http.GetStringAsync("https://example.com")
b := http.GetStringAsync("https://example.org")
Await(Task.WhenAll(a, b))
MsgBox StrLen(a.Result) " and " StrLen(b.Result)

Reacting without blocking at all.

#Import "Ks" { Task, Clr, Await }

http := Clr.System.Net.Http.HttpClient()
http.GetStringAsync("https://example.com").Then(Show)
Persistent

Show(t) {
    if t.Status = "Error"
        MsgBox "failed: " t.Error.Message
    else
        MsgBox StrLen(t.Result) " characters"
}

Racing the user against real work, which is what Source is for.

#Import "Ks" { Task, Clr, Await }

gate := Task.Source()
Hotkey "Esc", (*) => gate.Resolve("cancelled")

http := Clr.System.Net.Http.HttpClient()
winner := Await(Task.WhenAny(gate.Task, http.GetStringAsync("https://example.com")))

MsgBox winner = "cancelled" ? "you gave up" : "downloaded " StrLen(winner) " characters"
