#CSharp [Keysharp]

Embeds C# in a script. The C# is compiled into the script's own assembly, alongside the code generated from the script itself, so calling it needs no interop layer and no separate build step.

#CSharp
C# members
#EndCSharp

#CSharp "File.cs"

Note: This is for the handful of paths where AutoHotkey-level semantics cost too much — tight numeric loops, buffer and pixel work, repeated DllCall. It is not a general substitute for script code, and it does not make calls cheaper. See Performance.

Platforms: Verified on Windows and Linux. The implementation is platform-neutral; it has not yet been verified on macOS.

Parameters

File.cs

Type: String

Reads the C# from a file instead of from a block.

A relative path uses the module search path, not #Include's resolution: the directory of the file containing the directive first, then each configured search directory in order. The first existing file wins, and a miss names every directory that was tried. %A_ScriptDir%-style path variables expand here as they do in an #Include path.

The working directory is never consulted, deliberately: when a script is built by the compile daemon the working directory is the Keysharp install directory, so a path resolved against it would read from somewhere the script author cannot predict.

Unlike a module name, the path is taken as written — no extension is appended and no __Init lookup happens, because this names a file rather than a module.

Prefer this once the C# outgrows a few lines: a real .cs file gets syntax highlighting and can use editor completion when the editor is configured for a class-member fragment. The file contains members for the directive's scope, not a standalone namespace or containing class. This parameter is not an expression and does not accept variable references.

What the script can see

At module scope, a public static method becomes a script function within its declaring module, while public static fields and properties enter the module's variable store. Anything that is not public is a C# helper which the script cannot call. A module-scope public method which is not static is rejected because a module has no instance.

An explicit { Name } import can request any public static module method. Add [Export] to include one in wildcard imports, matching the script export keyword, or [Export(Default = true)] to match export default and bind it for a bare import. The attribute is valid only on public static methods at module scope.

In a class-body block, public methods and public property accessors are script-visible. A private or protected accessor remains a C# helper, and an init accessor is read-only after construction. A field is never script-visible, but it may hold C#-side state shared by that class's blocks.

#CSharp
static long[] scratch = new long[256];    ; not public: not a script variable
static long Helper(long n) => n * 2;      ; not public: not a script function

public static long Doubled(long n) => Helper(n);
#EndCSharp

MsgBox Doubled(21)   ; 42

At the top level of a script or module, the block's members become members of that module. A name that collides with a script variable or function, or with a name Keysharp generates, is reported against the block. A block may also appear in a class body.

Blocks in a class

A block written in a class body declares members of that class, so a fast path can live with the code it belongs to instead of taking a name in the script's global scope.

A static member receives its receiver as an ordinary leading parameter, before the arguments the script passes — the object for an instance member, the class itself for a class-static one. This is the same implicit this slot AutoHotkey uses: a script-declared static Stat(a,b,c) likewise reports four required parameters.

By convention it is written object @this, matching what Keysharp generates for a script-declared method, but the name is yours to choose and is not checked. (@this is C#'s escape for using the reserved word this as an identifier.)

Omitting it altogether is a different matter, and is reported at compile time: a public static method whose first parameter could not hold a receiver — because there is none, or because it is a value type, a string, an array, a pointer, or a params/by-ref slot — would otherwise have its first real argument handed the object. Left alone that surfaces at the call as "Too many arguments provided", or, for a variadic member, as a silently extra leading element in the params array. [Static] is not exempt: it selects which receiver arrives, never whether one does.

Since every such method is static in C#, C#'s own static is not what decides whether the script sees an instance member or a class-static one. The [Static] attribute does, and so does prefixing the name with static:

class Vec {
    __New(x, y) => (this.x := x, this.y := y)

    #CSharp
    ; An instance member: called as vec.Len2(scale), with vec as @this.
    public static object Len2(object @this, double scale)
    {
        var x = (double)Script.GetPropertyValue(@this, "x");
        var y = (double)Script.GetPropertyValue(@this, "y");
        return (x * x + y * y) * scale;
    }

    ; A class-static member: called as Vec.Origin().
    [Static]
    public static object Origin(object @this) => "0,0";

    ; Not public, so it needs no receiver: the script cannot call it, but this block can.
    static long Twice(long n) => n * 2;
    #EndCSharp
}

v := Vec(3.0, 4.0)
MsgBox v.Len2(2)      ; 50.0
MsgBox Vec.Origin()   ; 0,0

Members declared this way are registered exactly like the ones Keysharp generates for the class's AutoHotkey-declared methods, so they behave identically in every respect the script can observe: an instance member is not reachable through the class, a static one is not reachable through an instance, and the two sides may share a name without either shadowing the other. Ordinary parameters follow the receiver as usual — typed, optional or params:

#CSharp
[Static]
public static long Sum3(object @this, long a, long b, long c) => a + b + c;

; The `static` name prefix instead of the attribute; the script sees Vec.Scaled().
public static long staticScaled(object @this, long n) => n * 10;

; Variadic: the receiver is its own parameter, so the array holds only the real arguments.
[Static]
public static long Count(object @this, params object[] args) => args.Length;
#EndCSharp

A class-static property is written as its accessor method — staticget_Name or staticset_Name — because a property has no parameter list to receive the class in. So public static long staticget_Answer(object @this) => 42; is read by the script as Vec.Answer.

A C# instance member is also accepted, and declares no receiver, because C# binds one for it. This is also the only way a property can get one, a property having no parameter list to declare it in — so a public static property in a class body is rejected. Both methods and properties work:

#CSharp
public object Thrice(long n) => n * 3;   ; called as v.Thrice(4)
public long Half => 21;                  ; read as v.Half
#EndCSharp

A nested class gets its own block, in its own type. Non-public members are scoped to the class they were written in, so two classes may each declare a private helper of the same name without colliding.

Arguments and return values

Values crossing the boundary are converted with AutoHotkey's rules, not the CLR's, so a typed C# parameter accepts ordinary script values:

#CSharp
public static long SumSquares(long n)
{
    long acc = 0;
    for (long i = 1; i <= n; i++) acc += i * i;
    return acc;
}
#EndCSharp

MsgBox SumSquares(4)      ; 30
MsgBox SumSquares("4")    ; 30 — a numeric string converts, as "4" == 4 does
MsgBox SumSquares(4.0)    ; 30 — a Float truncates toward zero

Only a genuinely non-numeric value raises, and it raises a catchable TypeError, exactly as 1 + "abc" does. Integer-family and floating-point return types are normalised to Integer and Float, so results behave like any other script value.

A returned CLR value which has no native script representation is wrapped with the same objects used by Clr: System.Type becomes a ManagedType, and other CLR objects and value types become a ManagedInstance. This also applies when the declared return, property or field type is object. Passing a ManagedInstance back to C# unwraps its payload for a matching reference or value type and for an object target; ManagedType similarly unwraps for a System.Type-compatible target.

The exported boundary supports objects and reference types, strings, Booleans, integer-family types, float/double, and params object[]. Signatures which the script dispatcher cannot represent are rejected: ref/out/in, pointers and by-ref returns, char, decimal, nullable and tuple types, Span<T>/ReadOnlySpan<T>, typed params arrays, and generic exported methods. Make such a method non-public when it is only a C# helper.

Note: This is a check of the written type name — no C# name binding happens during lowering — so System.Char is recognized like char, but a using alias for a rejected type, or a user-defined ref struct, is not caught at compile time. Such a member fails when it is first called instead.

Sharing state with the script

Module globals are static fields of the same class, so C# reads and writes them directly — in lowercase, since that is the name actually generated and C# is case-sensitive:

global Hits := 0

#CSharp
public static long Tally(long n)
{
    hits = (long)hits + 1;    ; the script's `Hits`
    return n;
}
#EndCSharp

A global arrives as an unconverted value, and the script decides its type — Threshold := 1 stores an Integer and Threshold := 0.75 a Float, so a C# cast is not safe on one. Passing a global as a parameter instead is both safer and faster: the value is converted once at the boundary, and the body works with a real double.

Namespaces and preprocessor symbols

Every script module has its own inline C# syntax tree. A using at the top of any block is pooled across that module's tree, so it is available to later module and class blocks in the same module. It cannot leak into another module, and two modules may give the same alias different meanings. Already in scope in each module: System, System.Collections.Generic, System.Runtime.CompilerServices, System.Runtime.InteropServices and Keysharp.Runtime.

Keysharp.Builtins is deliberately not imported: its Array, String and Buffer would be ambiguous with the System types of the same name. Name those types in full, or import the namespace and resolve the ambiguity for that module.

Aliases and using static use ordinary C# syntax. A using may also be guarded by #if; only the active branch is imported. Keysharp normalizes global using to an ordinary module-local using. Otherwise C# would apply it to every syntax tree in the compilation and break module isolation.

The symbols active at the directive's source position apply inside its block, including around using directives, so #if WINDOWS selects the same branch on both sides and a later #Define or #Undef does not change an earlier block. Imported modules retain their own symbols. Note that Keysharp matches #Define names case-insensitively while C# does not.

Pointers and unsafe code

Pointer code is allowed, with C#'s own unsafe keyword as the only opt-in, exactly as in any other C# project. The directive takes no options.

Know what that costs: an out-of-bounds pointer write raises an AccessViolationException, which .NET does not deliver to a managed catch. The process disappears with no OnError, no error dialog and no OnExit — a silent death for a background hotkey script. This is the same exposure DllCall and NumPut already carry, which is why it is not gated separately here.

Errors

Syntax, boundary and name checks which Keysharp performs while lowering point to the authored script or C# file. Later Roslyn binding errors point to the generated module-specific inline C# unit. Keysharp does not add #line mappings, consistently with script runtime locations not generally tracking original source lines.

An exception thrown inside inline C# is mapped to the matching Keysharp error before it reaches the script, so an ordinary try intercepts it:

#CSharp
public static long Boom(long i)
{
    var a = new long[2];
    return a[i];
}
#EndCSharp

try
    Boom(5)
catch IndexError
    MsgBox "caught"

Performance

A call into inline C# is dispatched like any other script function call, so the directive does not make calls cheaper — it makes bodies cheaper. Put the whole loop inside the C#: one call that runs a million iterations is the win; a million calls into a one-line helper is slower than staying in script code, because it pays the dispatch a million times and gains nothing.

For bulk numeric data, hand C# a Buffer rather than an Array. Array element access goes through the same conversion machinery a script uses, so it stays script-speed even when called from C#, while a Buffer's memory can be walked directly as a Span.

Scripts that do not use this directive are unaffected: the wider framework reference set it needs is only added when a #CSharp block is present.

Remarks

All blocks in one script module form one C# syntax tree, so a later block in that module can use a type declared in an earlier one. Another module has a separate tree and using pool. Members still land in the type the block's scope names — the module, or the class it was written in — which is what keeps a class block's private helpers from colliding with another class's.

A block cannot appear inside a function, or inside a block such as an If body: there is no type there for its members to become members of. Like other directives, #CSharp cannot be executed conditionally.

Compiled scripts carry their inline C# as ordinary compiled code, so nothing extra is needed on the machine that runs one.

--transpile writes a tooling view of the inline C# to a separate Scriptname.inline.cs beside the generated Scriptname.cs. In a multi-module script this view concatenates the module-specific units which Roslyn compiles as separate trees.

Security: Inline C# runs with the script's full privileges, and can do anything the process can. It is the same trust decision as DllCall or Clr, and it is the script author's.

Examples

Runs a hot numeric loop in C#. The whole loop is inside, so the script pays one call.

#CSharp
public static long Collatz(long start, long limit)
{
    long best = 0, bestN = 0;
    for (long n = start; n < limit; n++)
    {
        long x = n, steps = 0;
        while (x != 1) { x = (x & 1) == 0 ? x >> 1 : 3 * x + 1; steps++; }
        if (steps > best) { best = steps; bestN = n; }
    }
    return bestN;
}
#EndCSharp

MsgBox "longest chain under 1e6 starts at " Collatz(1, 1000000)

Walks a screen capture's pixels directly, using C#'s own unsafe for the pointer.

#CSharp
using Keysharp.Builtins;

public static unsafe long CountNear(Buffer buf, int argb, int tol = 16)
{
    int wr = (argb >> 16) & 0xFF, wg = (argb >> 8) & 0xFF, wb = argb & 0xFF;
    var px = new System.ReadOnlySpan<byte>((void*)buf.Ptr, (int)(long)buf.Size);
    long hits = 0;
    for (int i = 0; i + 3 < px.Length; i += 4)
        if (System.Math.Abs(px[i] - wr) <= tol
         && System.Math.Abs(px[i + 1] - wg) <= tol
         && System.Math.Abs(px[i + 2] - wb) <= tol) hits++;
    return hits;
}
#EndCSharp

Img := Image.FromRect(0, 0, A_ScreenWidth, A_ScreenHeight)
MsgBox CountNear(Img.GetPixelData(4), 0xFF3B30, 20) " reddish pixels"
